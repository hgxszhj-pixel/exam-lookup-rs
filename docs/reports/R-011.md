## 改动

### 1. `crates/exam-app/src/state.rs`

新增 `AppState::rebuild_index(data_root, db_path) -> Result<BuildStats, String>`:

- 写 `DbStatus::Unloaded`(UI 看到过渡态)
- `IndexBuilder::open(db_path)` → `rebuild(data_root)`
- 用 `OpenFlags::SQLITE_OPEN_READ_ONLY` 打开新 conn,原子替换 `self.db: Mutex<Option<Connection>>`
- 写 `DbStatus::Ready { questions: stats.questions }`

API 边界:**SettingsPage 永远以 settings 里的最新值调用**,避免 UI 编辑了 signal 却没保存就重建的歧义(详见 settings.rs 注释)。

### 2. `crates/exam-app/src/ui/settings.rs`

- 顶部增加 `DbStatus` 徽章(Ready{N} 绿 / Error 红 / Unloaded 灰)沿用 Phase J 配色 token。
- "保存" 按钮旁加 "重建索引" 按钮:
  - 读 `state.settings`(持久化值,不是 signal)
  - 调用 `state.rebuild_index()`
  - 反馈 `banks/questions/cards/errors` 四元统计
  - `rebuilding` signal 控制 disabled + 文案("重建索引" ↔ "重建中…")

## 踩坑

1. **`SearchHit` 字段名**:`stem` / `source` 在我记忆中已 rename,实测为 `question` / `src`;以 `cargo check` 报错修正为准,不靠记忆。
2. **dioxus `use_signal` 不能直接 `move` 进 onclick 闭包外再用** — 每个 signal 单独 `set` 即可,无需拆 `let mut` 引用。
3. **db_status 在 rebuild 期间应置 `Unloaded` 而不是保留旧 `Ready`** — 避免 UI 显示"就绪 1760 题"但搜索命中是新 DB 的不一致态(这里 rebuild 单调很短,但语义要正确)。

## 未做(留给后续)

- **数据根变更不重启的「立即生效」**:Phase H 设计是把"重建"和"切换路径"绑一起(Settings → 保存 + 重建两步)。如需"只换 data_root 不重建",另开 Phase I+(现在的 rebuild 必然 rebuild data_root)。
- **后台线程 + 进度条**:当前重建在 UI thread 同步执行,1760 题 / 1278 cards 在 0.37s 完成体感无感;若上 10k+ 文档,再切 `dioxus::spawn` + 进度 signal。
- **多 data_root 缓存切换**:现在 settings 是单 data_root。多份题库(保密 + 网信 + 司法)需要 cache pool 概念,属 Phase L+。
