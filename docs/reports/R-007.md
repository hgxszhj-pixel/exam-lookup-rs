# R-007 反爬 / 限流 / 网络 IO 失败处理

## 议题
- 计划 `source/*.rs` 后续可能加 `async fn fetch()` 走 HTTP(reqwest)。
- 题库外部抓取场景必然遇到:反爬(WAF / JS challenge)、限流(429)、网络中断、DNS 失败。
- 无重试策略会把单次失败放大成用户体验崩溃;盲目重试会触发限流升级。

## 决策
**单次失败 → 写 cache(notes 标 error)+ UI 显示「获取受限」+ 不自动重试。**

具体:
- `crates/exam-engine/src/scheduler.rs::Scheduler::tick()` —— load 失败时仍 `cache.upsert(CacheStatus::Expired, notes=err.to_string())`。
- CLI `exam-cli run` 在 tick 后打印失败 source,但继续跑下一个 source。
- GUI 不暴露「重试」按钮;用户重启 app 才再次触发。
- Phase F 内不实现 `async fn fetch()`(题库主路径是本地 JSON,不需要 HTTP)。

## 不引入的东西
- ❌ 指数退避重试(backoff) —— 单次失败后写入 cache 已记录,重启即重跑,无需自动 backoff。
- ❌ 分布式限流协调(只有本地 desktop,无意义)。
- ❌ 反爬绕过 —— 计划 out-of-scope:本项目不抓取外部题库(plan §9)。

## 验证
- `scheduler::tests::tick_records_error_in_cache_notes`:mock failing source,验证 cache notes 含 `"simulated"`,status=`Expired`。
- 集成测试:`run_loop_for` 持续触发时,失败 source 不会卡死线程。
