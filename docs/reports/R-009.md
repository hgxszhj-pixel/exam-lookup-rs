# R-009 搜索排序与 Python `solve.py::lookup` 的差异

## 议题
- Python 端 `solve.py::lookup` 使用「先 `nq` 精确 → 失败 `SequenceMatcher.ratio()` 全表模糊」的两段式查找。
- Rust 端使用「`nqstem` 精确 → FTS5 bm25 → LIKE 子串」的三段式查找。

## 行为差异

| 维度 | Python | Rust | 影响 |
|------|--------|------|------|
| 完全匹配 | `nq == ?` 1 条 | `nqstem == ?` 1 条 | 一致 |
| 子串匹配 | `nq LIKE '%?%'` | `nq LIKE '%?%'` | 一致 |
| CJK 模糊 | `SequenceMatcher.ratio` 编辑距离 | LIKE 子串兜底 | 排名差异 |
| 排序 | 精确优先;模糊时 ratio 降序 | bm25 升序(数值越小越相关) | 顺序可能反转 |
| 阈值 | ratio ≥ 0.6 视为命中 | 无阈值(返回所有命中) | 召回差异 |

## 已知偏差案例
- 「网络安全」查「网咯安全」(错别字):Python ratio ≈ 0.67,可能命中;Rust 不会命中。
- 「密码学」查「密码」(前缀):Python ratio ≈ 0.67,可能命中;Rust LIKE 命中。

## 缓解
- 排序用 bm25(数值越小越相关),CLI 输出已带分数便于对照。
- 若 R-009 偏差导致用户体验下降,后续可:
  1) 引入 `strsim = "0.11"` crate,做 ratio 排序作为第四段兜底
  2) 用 `cargo fuzz` 跑回归 case(空 query / 超长 query / 全角符号)
