# R-008 大文件 docs/ 索引启动慢

## 议题
- 若 `docs/` 目录包含大量 PDF / HTML,`IndexBuilder` 启动时一次性扫描 + 解析会阻塞 GUI 加载。
- 实测当前 Python 项目 `docs/` 目录小(< 100MB),扫描 < 1s,无明显问题。
- 后续若用户塞入整本教材(单 PDF > 50MB),启动可能 5-10s 卡顿。

## 决策
**Phase F 范围内 `IndexBuilder` 不阻塞 GUI 启动,Phase F+ 视情况拆分。**

当前具体落地:
- `crates/exam-app/src/state.rs::AppState::bootstrap()` → 同步打开 SQLite(`Connection::open`)。
- 当前 `crates/exam-engine/src/index.rs::IndexBuilder` 在 CLI 端调用(`exam-cli index` / `load`);**GUI 启动不调用 IndexBuilder**,只读已存在的 `questions.db`。
- GUI 启动阻塞仅 = SQLite open + `count(*)`(< 50ms 1k 题)。

## Phase F+ 优化路径(若需要)
1. `IndexBuilder` 改异步 + 后台线程 + 进度条。
2. 拆分:启动时先 `count(*)` 显示「题库 N 题」,后台跑增量 rebuild。
3. 加文件 mtime 索引:启动扫描 `banks/*.json` mtime,只在变更时重建。

## 验证
- 当前:`AppState::bootstrap()` 单元测试可手测 < 100ms(无 Phase F 测试,留作 integration test)。
- GUI 烟测(Phase E):启动 → 首页渲染 < 1s(已验证)。

## 状态
- 落地:Phase E 不阻塞。
- Phase F+ 优先级:低(用户当前数据量不触发)。
